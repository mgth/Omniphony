Distance Diffuse
Distance Diffuse blends each object with a mirrored version of itself (opposite horizontal direction) depending on distance. Close objects become wider/more diffuse, while far objects stay mostly direct.

Threshold: distance where the blend reaches 100% direct.
Curve: transition shape (faster or slower near-field blend).
Spread from Distance
Spread from Distance derives spread from listener distance instead of relying only on object_size.

The distance curve is mapped into the global spread min/max range, so close objects can stay broad while far objects collapse toward the configured minimum.

Range sets where the distance contribution reaches zero. Curve shapes how quickly that collapse happens. Size→Spread mode still controls how object size is converted when size-based spread is in use or compared against the distance result.
Trails
Trails show each object's recent movement history in the 3D view.

Mode: choose between a classic line or a diffuse particle trail.
Duration: how long trail points stay visible before fading out.
Effective render position
Shows an estimated rendered position inferred from the speakers that are currently carrying the object.

The marker is meant as a visual sanity check: it helps reveal when the rendered energy center drifts away from the nominal object position.

The thin line connects the nominal object position to that estimated effective render point.
OSC
Host: target host used for OSC communication.

Omniphony Port: port where `orender` sends state and receives control.

Listen Port: local port used by the visualizer to receive OSC. `0` lets the system choose one automatically.
Omniphony Studio About
Omniphony is an open spatial-audio project built around realtime rendering, transport, control, and monitoring tools for object-based audio workflows. Omniphony Studio is the visual control surface of that ecosystem.

Room Geometry
Room geometry defines the physical room dimensions, in meters, used to map normalized scene coordinates to meters.

Width is the reference and pins the scale; Front, Rear, Height and Lower are entered directly in meters. The Y center blend only appears when Front and Rear differ.

These values affect distance-based processing and the spatial interpretation of the 3D scene.
Latency controls
This panel groups global far-mode actions and local resampling-controller parameters.

High-recover entry margin (high-side error) defines when high-recover / far-mode actions become eligible; Low-recover entry margin is the low-side trigger that rebuilds latency.
Hard recover high, hard recover low, silence in far mode, and fade-in on near return are global latency-recovery actions.
Adaptive resampling, update interval, adaptive max, adaptive KP, adaptive Ki, and integral discharge belong to the local PI resampling controller and only matter when adaptive resampling is enabled.
Latency Gauges
raw is the instantaneous measured latency; its markers show the recent low/high window.

ctrl is the smoothed control latency used by the adaptive logic. The target marker and far-threshold markers show where the controller is trying to stay and when far-mode recovery can engage.

resample shows the current adaptive correction around neutral 1.0. Left means slower, right means faster. The panel also exposes the active band/state so you can see whether the system is near, far, or actively recovering.
Evaluation mode
Evaluation mode controls how speaker gains are computed for each object position.

Realtime computes directly at runtime. Precomputed polar and precomputed cartesian trade memory for faster lookups and more stable cost. Auto lets the renderer choose the best available path for the current backend and tables.
Render backend
Distance model
Distance model controls how object gain falls with distance before any diffuse or spread-specific processing is applied.

None keeps distance neutral. Linear and quadratic apply progressively stronger attenuation. Inverse-square is the steepest and is closest to a simple physical falloff.
Audio Input
This section defines where incoming audio comes from and how Studio describes that source to the renderer.

Mode chooses between a bridged file/process input and a live device/backend path. The remaining fields define the bridge binary, imported layout, channel format, mapping, and channel handling that the renderer should expect.
Input clock
Clock selects which side is treated as the timing reference for the live input path.

DAC follows the output device clock. PipeWire follows the PipeWire graph clock. Upstream (advanced) trusts the capture source or bridge clock — the sink runs without a driver flag and requires an external PipeWire driver in the chain (e.g. JACK or a monitoring client). Without one, playback stalls. Prefer DAC unless you know you need this.

This choice matters when diagnosing drift, latency correction, or which side should adapt to the other.
LFE handling
LFE controls what happens to the input stream’s low-frequency effects channel.

Object turns it into a spatial object. Direct keeps it as a dedicated direct-fed LFE path. Drop ignores it entirely.

Choose this according to how the source material was authored and how your output layout expects bass content to be routed.
DRC and loudness
This section combines codec-side dynamic range control with renderer-side loudness correction.

DRC selects the metadata-driven compression profile, and DRC weight blends how strongly that profile is applied.

Loudness / Dialog Norm applies a gain correction derived from the source metadata so playback lands closer to the configured target level.
Heatmaps
Heatmaps visualize how the renderer distributes energy across the listening area or volume.

Heatmap slices shows sectional planes, Heatmap volume shows volumetric sampling, and Heatmap band selects which frequency band is displayed.

Heatmap values controls sampling density, and Max sphere size caps the display size of each sample point. Some views are only meaningful when the current evaluation mode has the required precomputed data.

Objects energy field shows the theoretical acoustic energy radiated by the objects themselves (inverse-square from each object's current level), accumulated into stacks of slices that can be cut along any of the three axes (Width, Depth, Height). Planes per axis, Field resolution, Falloff radius and Field opacity tune the display.
Ramp mode
Off: disable interpolation and jump immediately to the new target.

Per frame: apply one interpolation step per decoded audio frame. This is lighter and more stepped.

Per sample: apply one interpolation step for every rendered sample. This is the smoothest mode and matches the previous default behavior.
